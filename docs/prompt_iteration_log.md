## 🎯 起点:V0 基线评估

**评估集**:50 题(5 类别 × 3 难度 × 6 维度指标)

**V0 数据**:
- 总分:0.818
- cross_paper:0.665 ⚠️ Pattern Bad Case(其他类 0.85+)
- 其他类:0.83-0.88
- Bad Cases(<0.5):0 题

**发现**:cross_paper 类显著低于其他类,差距 20%。**这不是"灾难性失败",是"系统性短板"**。

---

## 🔍 诊断阶段:验证 3 个假设

抽样 cross_paper 最高分(eval_034 = 0.827)和最低分(eval_040 = 0.6),发现:

### 假设 H1:**检索阶段"单篇垄断"**

```
eval_040 的 top 5:transformer × 4 + rag × 1 + react × 0
→ react.pdf 完全没命中
→ Recall@5 = 1.0(因为有 rag) — 是假阳性
→ 真实覆盖率 67%(2/3 篇)
```

### 假设 H2:**Prompt 没引导"部分回答"**

```
V0 Prompt:"如果片段不足以回答,直接说基于现有片段无法确定"
→ Claude 看到缺一篇,选择完全拒答
→ 没尝试"答能答的部分"
```

### 假设 H3:**Recall@5 指标过宽**

```
当前:top 5 有 ≥1 篇 expected 就算 1.0
→ 应改为 "Coverage" 覆盖率
→ 这是评估方法的"假阳性"
```

**3 个假设全部成立**。

## 🛠️ V1 Prompt 实验:加"跨论文场景指引"

**改动**:在 V0 基础上加 1 段(120 字):
- 片段不全时,部分回答 + 标注未覆盖
- 不要因为"缺一篇"完全拒答

**V1 数据**:
| 维度 | V0 | V1 | 变化 |
|---|---|---|---|
| 总分 | 0.818 | **0.824** | +0.6% |
| cross_paper | 0.665 | **0.707** | **+6.3% ✅** |
| out_of_scope | 0.830 | **0.793** | -4.5% 🟡 |
| Refusal Rate | 1.0 | 0.9 | -10% 🟡 |

**判断**:cross_paper 目标达成,但引入 out_of_scope 副作用。**假 trade-off**。

## 🔬 V2 Prompt 实验:加 3 段"特别警告" — **翻车**

**改动**:在 V1 基础上加 3 段(共 280 字):
1. 对比类问题:必须双方都有实质内容
2. 单位类问题:必须精确匹配类别
3. 时序边界:论文发表后的概念不能基于"已知"答

**单题验证(3 题全过)**:
- eval_044(BERT vs Transformer):正确拒答 ✅
- eval_048(美元成本):明确说明 FLOPs ≠ 美元 ✅
- eval_049(ReAct vs CoT):正确标注"根据 ReAct 论文" ✅

**完整 50 题数据(翻车)**:
| 维度 | V1 | V2 | 变化 |
|---|---|---|---|
| 总分 | 0.824 | **0.809** | **-1.5% 🔴** |
| cross_paper | 0.707 | 0.705 | 持平 |
| out_of_scope | 0.793 | **0.760** | **-3.3% 🔴** |
| metadata | 0.900 | 0.887 | -1.4% |
| definition | 0.856 | 0.835 | -2.1% |
| detail | 0.865 | 0.856 | -0.9% |

**判断**:V2 不仅没消除 V1 的 trade-off,反而**全面拖累总分**。

---

## 🧠 翻车根因分析

### 根因 1:**Prompt 长度反规律**

```
V0:200 字 → 总分 0.818
V1:320 字 → 总分 0.824 (+0.6%)
V2:600 字 → 总分 0.809 (-1.5%)

→ Prompt 越长,模型注意力越分散
→ 关键指令权重下降
→ "加规则"不是越多越好
```

### 根因 2:**单题测试 ≠ 全局测试**

```
我挑的 3 题是 V1 失败案例 → V2 自然会修
但 V2 也可能损害"没出问题的 47 题"
→ 局部最优 ≠ 全局最优
```

### 根因 3:**消除 trade-off 不能靠"打补丁"**

```
真正消除假 trade-off 可能需要:
- 重构 Prompt 结构(不是加段落)
- 改检索策略(per-document quota)
- 用规则引擎做意图分类(分流不同类型的题)

→ 加 3 段警告是"打补丁",治标不治本
```

---

## ✅ 最终决策:**回滚 V1**

**理由**:
1. **V1 是当前数据最优版本**(总分 0.824,cross_paper 已修复)
2. V2 是失败实验,**回滚是止损,不是认怂**
3. **沉没成本不该影响新决策** — 不能因为"写了 V2"就不回滚

**操作**:删除 V2 的 3 段"特别警告",保留 V1 的"跨论文场景指引"。

---

## 💎 3 个核心教训(简历 / 面试用)

### 教训 1:**Prompt 优化必须做减法**

"加规则"是新手陷阱。**真正的 Prompt 工程是'精简 + 精准',不是'堆叠 + 详尽'**。
Prompt 长度反规律:长 Prompt → 注意力分散 → 关键指令失效。

### 教训 2:**完整回归测试不可省**

3 题测试是"代表性测试",**不等于"全局测试"**。
AI 产品的迭代必须看"所有题的总和",不能只看"修复的题"。

### 教训 3:**翻车也是数据**

PM 的诚实不在于"假装没失败",而在于**"敢于回滚 + 资产化失败"**。
本次翻车让我学到的,比 V1 成功的还多。

---

## 🎤 面试可用的 4 个金句(本日产出)

1. **"消除假 trade-off"**:很多 trade-off 来自 Prompt 措辞不精细,而不是产品规律必然。
2. **"Prompt 长度反规律"**:Prompt 越长,效果越差。做减法比做加法难。
3. **"快速失败 + 快速止损"**:V2 翻车立刻回滚,不为沉没成本付出更多。
4. **"翻车资产化"**:把失败实验写成日志,变成简历可用的"诚实案例"。
